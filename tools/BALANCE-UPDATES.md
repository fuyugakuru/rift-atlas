# Обновления игровых данных

`patch-updates.yml` проверяет официальный сайт Riot каждый час (запуск GitHub может задерживаться). Номер патча и правки баланса собираются отдельно. Посетители сайта не запускают сборщик.

1. `update-patches.cjs` находит последнюю публикацию.
2. `update-balance.cjs` извлекает правки чемпионов, предметов и рун, сохраняя режим. Текущая статья перечитывается даже при неизменном номере патча: это позволяет заметить исправления Riot.
3. `balance-candidates.js` содержит последние 12 собранных публикаций; `balance-catalog.js` — исходные тексты сайта для формы проверки. При ошибке парсера предыдущий снимок остаётся на месте.
4. Администратор открывает «Панель модерации → Обновления игры». Совпавшие числовые последовательности подставляются в предложенный текст. Неоднозначные изменения требуют проверки/редактирования полного текста, а не случайной замены чисел. Добавление нового чемпиона или предмета не автоматизируется.
5. После проверки и подтверждения `balance_publish` сохраняет полную новую версию записи в Supabase. Она применяется на страницах через `balance-live.js`; редактировать сотни HTML-файлов для каждой правки не требуется. Старые публикации сохраняются в закрытом журнале. В обычный режим можно публиковать только изменения `classic`.

Первоначальное подключение: применить SQL 029 один раз и загрузить файлы сайта + изменённый workflow в GitHub. SQL 029 уже применён 26.11.2026. Повторный запуск не нужен. Секретный ключ Supabase в GitHub добавлять не требуется. Публиковать может только существующая роль `admin`; модераторам и обычным пользователям доступ на запись закрыт на сервере.

Ограничения: это проверяемое обновление по официальным патчам, а не полный машиночитаемый API Riot. Изменения структуры публикации, неизвестные поля и расхождение старых значений требуют внимания администратора. В отсутствие Supabase сайт показывает сохранённые статические тексты. Обновления в БД не переписывают исходные JSON/HTML на диске; при дальнейшей генерации страниц одобренная версия в БД остаётся приоритетной. Текст навыков/описаний обновляется; пересчёт формул урона, изменение состава рецептов, новых ассетов и автоматическая смена билдов сюда не входят.
