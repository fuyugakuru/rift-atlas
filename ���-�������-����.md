# Rift Atlas: полный разбор кода

Это обычный многостраничный сайт на HTML, CSS и JavaScript. React, база данных и сервер приложений здесь не используются. Netlify хранит и раздаёт готовые файлы. Все исходники открыты для редактирования.

## 2. Что происходит при открытии страницы

1. Браузер получает HTML-файл, например champions.html.
2. Строка `<link rel="stylesheet" href="style.css">` подключает оформление.
3. `<script src="data.js" defer></script>` загружает данные.
4. `<script src="app.js" defer></script>` подключает поведение.
5. `defer` означает: выполнять скрипты после разбора HTML. Их порядок сохраняется, поэтому app.js уже видит данные из data.js.
6. JavaScript проверяет, какие элементы есть на странице, и запускает только нужный раздел.

Переход по `<a href="mel.html">` открывает отдельный документ. Здесь нет скрытого переключателя экранов: это действительно разные страницы.

## 3. HTML: содержание и структура

На каждой странице повторяются общие элементы:

```html
<aside class="sidebar">...</aside>
<div class="workspace">
  <header class="topbar">...</header>
  <main id="main">...</main>
  <footer>...</footer>
</div>
```

`aside` — боковое меню. `header` — верхняя строка. `main` — содержание текущей страницы. `footer` — подвал. `nav` объединяет ссылки навигации, `section` — отдельный раздел, `article` — самостоятельную карточку.

`class="panel"` связывает элемент с CSS-правилом `.panel`. Один класс можно повторять. `id="champ-search"` — уникальное имя поля для JavaScript; одинаковые id внутри одной страницы использовать нельзя.

```html
<a href="#abilities">Способности</a>
<section id="abilities">...</section>
```

Ссылка с `#` прокручивает текущую страницу к разделу. `aria-label` подписывает элемент для вспомогательных технологий, `aria-pressed` сообщает состояние переключателя избранного. `hidden` скрывает элемент. Удалять эти атрибуты без причины не нужно.

## 4. CSS: оформление

В начале style.css находятся переменные темы:

```css
:root {
  --bg: #0c0e14;
  --panel: #13161f;
  --violet: #ae93fb;
}
```

`background: var(--bg)` берёт цвет из переменной. Меняя переменную, можно изменить общий цвет, не искать десятки отдельных правил.

Основные группы классов:

- `.sidebar`, `.workspace`, `.topbar` — каркас страницы.
- `.hero`, `.hero-image`, `.hero-shade` — главный баннер, изображение и затемнение для читаемости текста.
- `.champ-grid`, `.champ-card` — сетка и карточки чемпионов.
- `.panel`, `.item-grid`, `.badge` — панели, сетки предметов и метки.
- `.toolbar`, `.search`, `.chip` — поиск и фильтры.
- `.profile-hero`, `.abilities`, `.anchors` — страницы героинь.
- `.clock-panel`, `.timer-grid` — таймеры.

```css
.champ-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 20px;
}
```

`grid` создаёт сетку. `repeat(3, ...)` задаёт три равные колонки. `gap` — расстояние между карточками. `padding` — отступ внутри элемента, `margin` — снаружи. `border-radius` скругляет углы.

`position: fixed` закрепляет боковое меню на компьютере. `position: absolute` располагает изображение или подпись внутри родительского блока с `position: relative`.

В конце CSS расположены `@media`: при ширине до 760 px боковое меню становится верхним, а сетки переходят в одну колонку. `prefers-reduced-motion` отключает необязательные анимации по настройке устройства.

## 5. data.js: данные

Этот файл присваивает объект глобальному свойству:

```js
window.RIFT_DATA = {
  checked: '2026-11-08',
  champions: [],
  catalog: [],
  items: []
};
```

`champions` содержит три подробных гайда: id, имя, изображение, способности, примеры предметов, матчапы. `catalog` содержит официальный список. `items` — стартовую подборку предметов.

Это статические данные. Дата checked не обновляет их автоматически и не означает подключение к игровому серверу.

## 6. app.js: поведение

### Выбор элементов

```js
const data = window.RIFT_DATA;
document.querySelector('#champ-search');
document.querySelectorAll('[data-favorite]');
```

`querySelector` находит один элемент. `#` обозначает id, `.` — класс. `querySelectorAll` возвращает коллекцию. `[data-favorite]` выбирает элементы с этим атрибутом.

```html
<button data-favorite="mel">☆</button>
```

`button.dataset.favorite` вернёт строку `mel`. Так кнопка сообщает скрипту, к какому чемпиону относится.

### Избранное

`favorites` — массив id. `paintFavorites()` меняет звёздочки и aria-pressed. Обработчик click добавляет или убирает id. `localStorage` сохраняет список между посещениями в этом браузере. Это не аккаунт и не общая база пользователей. В другом браузере список будет другим. `try/catch` нужен, чтобы блокировка хранилища не сломала страницу.

### Поиск чемпионов

`normalize()` приводит текст к нижнему регистру и заменяет «ё» на «е». `filterChampions()` читает запрос, проверяет совпадение через `includes()`, учитывает выбранный фильтр и переключает hidden у карточек. Для официального каталога создаёт ссылки через `document.createElement('a')`.

`scope` хранит режим: all, guides или favorites. `URLSearchParams` читает `?favorites=1`, чтобы ссылка «Мой пул» сразу включала нужный фильтр. Русские имена трёх героинь и английские id проверяются вместе.

### Фильтр предметов

Если на странице найден `#item-search`, подключаются обработчики input и change. Они сверяют имя предмета и выбранный тип. Карточки не удаляются: скрываются через hidden.

### Контрпики

Если найден `#matchup-champion`, функция render находит выбранную героиню в data.champions и рисует её советы в `#matchup-result`. `esc()` заменяет специальные HTML-символы перед вставкой текста через innerHTML. В других местах, где разметка не требуется, используется textContent.

Это авторские советы, не рассчитанная статистика матчей. Выбор в выпадающем списке не обращается к API.

### Справочник таймингов

Страница timers.html больше не содержит секундомера: пользователь изучает время появления объектов.

- timings-data.js хранит массив RIFT_TIMINGS: id, название, категорию, время первого появления в секундах, возрождение, источник и примечание. null означает отсутствие проверенного значения.
- timings.js строит таблицу и хронологию через createElement и textContent. Поиск и фильтр читают тот же массив. Переключатель скрывает цифры для самостоятельного повторения.
- Мини-проверка использует только строки с заполненным first. Вопрос, варианты ответа и правильное время выводятся из одних данных. После ответа кнопки блокируются, подсвечивается правильный вариант, затем показывается результат. Повторный клик не увеличивает счёт.
- tools/timings-content.html — шаблон содержания. В конце tools/build.cjs он вставляется в общий каркас страницы, где подключаются два дополнительных скрипта с defer.

Чтобы изменить время, редактируйте timings-data.js. Сначала проверьте источник и правила режима. Не заменяйте null выдуманным числом. Значение первого появления — отметка с начала матча, возрождение — отдельный интервал после убийства.

В 6.2 и 7.0 описаны исторические изменения. Отображение их на странице не означает, что все последующие патчи полностью сверены. Эта оговорка видна посетителю.

## 7. Генератор страниц: tools/build.cjs

Этот Node.js-скрипт создаёт HTML и data.js из общих шаблонов. Объект guides содержит тексты трёх гайдов; items — предметы; nav — ссылки меню. Функция shell(file, title, body) создаёт общий каркас. card(c) создаёт карточку чемпиона. write(...) сохраняет страницу.

Зачем генератор: изменение меню или подвала сразу применяется к 11 страницам, вместо ручного редактирования каждой.

Важно: build.cjs перезаписывает HTML и data.js. Если изменили их напрямую и затем запустили генератор, ручные изменения пропадут. Для постоянных изменений редактируйте шаблон build.cjs. style.css и app.js генератор не перезаписывает.

Для генерации из папки сайта при установленном Node.js:

```text
node tools/build.cjs
```

Никакие библиотеки для этого не требуются. __dirname — папка самого скрипта; корень сайта вычисляется относительно неё, поэтому проект можно перенести на другой диск.

## 8. Загрузка данных: tools/fetch-data.cjs

Скрипт запрашивает публичные страницы Riot через fetch, читает встроенный JSON __NEXT_DATA__, сохраняет данные и загружает изображения в assets. Рекурсивная walk() обходит вложенные объекты. Функция asset() записывает изображение в файл.

```text
node tools/fetch-data.cjs
node tools/build.cjs
```

Это ручная операция. Она не обновляет автоматически патчи, советы, тарифы предметов или тайминги. Если Riot изменит формат страницы, парсер может перестать работать. После запуска проверяйте результат и содержимое перед публикацией. Дата проверки в шаблоне также должна быть пересмотрена человеком; не ставьте новую дату без проверки.

## 9. Примеры изменений

**Заголовок главной:** найдите в tools/build.cjs текст «Справочник» и измените HTML заголовка h1. Затем выполните build.cjs.

**Цвет интерфейса:** измените переменные в начале style.css. Перегенерация не нужна.

**Новый совет по Синдре:** измените guides.syndra в tools/build.cjs и перегенерируйте.

**Новый предмет:** добавьте объект в items в build.cjs. id должен быть уникальным. Чтобы включить его в гайд, добавьте этот id в массив items нужной героини.

**Новый подробный чемпион:** одного имени в каталоге недостаточно. Нужно расширить загрузчик, добавить гайд, данные способностей и изображения. Сейчас цикл загрузки намеренно ограничен тремя выбранными чемпионками.

**Новая страница:** добавьте ссылку в nav и вызов write с её HTML-содержимым.

## 10. Как публиковать обновления

1. Отредактируйте исходники. Если менялся генератор, выполните его.
2. Откройте index.html или локальный HTTP-просмотр и проверьте страницы.
3. Убедитесь, что поиск, избранное, фильтры и справочник таймингов работает.
4. В Netlify откройте существующий проект rift-atlas-wr → Deploys.
5. Загрузите папку сайта или ZIP, в корне которого находится index.html, а рядом CSS, JS и assets.
6. Проверьте Published и откройте публичную ссылку.

Netlify не читает файлы с диска E автоматически. Изменить файл в Visual Studio недостаточно: новую версию надо загрузить.

Не загружайте в публичную папку пароли, ключи или личные файлы. Исходный код этого статического сайта в любом случае доступен посетителю через браузер. Включённые в комплект файлы не содержат учётных данных.

## 11. Что ещё предстоит реализовать

Автоматическая лента патчей потребует серверного получения источников, проверки формата, кеширования и обработки ошибок. Статистике нужны легальный источник, регион, ранг и выборка. Полным сборкам и таймингам — проверенные данные текущей версии. Эти функции нельзя получить, просто изменив надпись в интерфейсе.

### Дополнение: источники и виды вопросов

В timings-data.js массив sources содержит несколько ссылок для одной строки: первое появление и возрождение могут быть описаны в разных патчах. reference=true помечает исторические справочные замеры. Такие строки показаны в таблице, но исключены из проверочных вопросов. respawnText используется для правил без одного числа: одно появление, расписание волн или противоречие источников. practice-mode выбирает вопросы первого появления, возрождения или оба вида. Варианты перемешиваются, повторный ответ не меняет счёт.

### Тест: 20 вопросов

Банк вопросов и случайная выборка вынесены в timing-quiz.js. create() выбирает 20 уникальных вопросов, включая правило об однократном появлении Герольда. При повторе подборка и варианты перемешиваются. Вопросы используют все строки таблицы, включая справочные данные. Интервал краба 120 секунд задан автором сайта и отмечен в данных. timings.js отвечает только за показ, выбор ответа и подсчёт результата. Старое описание ограничений банка выше заменено этой версией.

### Каталог всех чемпионов

champion-catalog.json содержит имена, фотографии, класс и сложность всех чемпионов. tools/expand-champions.cjs загружает каталог Riot, сохраняет изображения в assets/champions, создаёт отдельные страницы и сохраняет три подробных гайда. tools/build-catalog.cjs формирует карточки со ссылками внутри сайта. Избранное теперь доступно для всего каталога, фильтр «С гайдом» оставляет три подробных гайда. Для обновления каталога: node tools/expand-champions.cjs, затем node tools/build-catalog.cjs. Проверка загрузки данных: 09.11.2026.

## Линии чемпионов
champion-lanes.json хранит рекомендованные позиции каждого чемпиона. Источник распределения: https://www.wildriftfire.com/tier-list (09.11.2026). Изображения позиций: assets/lanes/. tools/profile-details.cjs добавляет строку «Линия» отдельно от класса персонажа. При изменении позиций обновите JSON и запустите node tools/profile-details.cjs.


## Навыки чемпионов
champion-abilities.json содержит 710 навыков: названия, русские описания и исходные ссылки Riot. Значки лежат в assets/abilities/. tools/fetch-abilities.cjs загружает данные с официальных русских страниц Wild Rift; tools/render-abilities.cjs создаёт карточки под основной информацией чемпиона. При сборке tools/profile-details.cjs восстанавливает этот блок автоматически. Для полного обновления удалите старый champion-abilities.json, запустите fetch-abilities.cjs, затем render-abilities.cjs. Текст Riot очищается от сторонних HTML-тегов; переносы строк сохраняются.

## Числовые значения умений
ability-values.json дополняет данные Riot числовыми описаниями из WildRiftFire: урон, коэффициенты, эффекты, перезарядка и стоимость. У каждого чемпиона сохранены источник и оригинальный английский текст. Перевод хранится отдельно; числовые токены защищены при переводе. У Кейна учтены обе формы; формула Q Рааста дополнительно сверена с Wild Rift Wiki. tools/fetch-ability-values.cjs загружает данные, tools/render-abilities.cjs показывает значения. Источник параметров указан под навыками. Это справочные данные внешнего сайта, синхронизации с клиентом игры нет.

## Сборки чемпионов
champion-builds.json хранит варианты сборок WildRiftFire по позициям, ссылку на источник и патч. tools/fetch-builds.cjs загружает предметы, стартовые предметы, руны и заклинания. Значки находятся в assets/builds/. build-labels-ru.json сопоставляет английские названия с русскими (общие названия из Riot Data Dragon, специфичные для Wild Rift добавлены отдельно; характеристики из ПК-версии не используются). tools/render-builds.cjs размещает блок перед навыками. Переключение позиции в app.js одновременно меняет предметы, руны и заклинания; эти сборки — варианты внешнего автора, а не гарантированно оптимальный выбор против любой команды.

## Расширенная проверка позиций и рун
champion-role-audit.json — сверка 142 чемпионов с Wild Rift Core; champion-builds.json объединяет варианты источников и хранит source/runeSource, runeStatus, equipmentVariants, situationalRunes, extraPositions. Дополнительные комплекты не копируют руны с другой позиции. Если полный набор не подтверждён, runeStatus=incomplete скрывает неподтверждённые руны. Редкие позиции без полной сборки находятся в extraPositions. При переключении позиции меняются источник и версия данных. Число доступных слотов и наборов проверено; сведения сторонних сайтов не гарантируют оптимальность и совпадение с текущим клиентом. Локальная версия содержит 231 вариант сборок и 84 ситуативные замены рун. Публикация новой версии приостановлена из-за лимита Netlify.

## Описания предметов и рун по нажатию
build-asset-details.json хранит 174 описания используемых предметов, рун и заклинаний, исходные тексты, ссылки и стоимость при наличии. tools/fetch-asset-details.cjs загружает подсказки WildRiftFire; для отсутствующих подсказок использованы страницы Wild Rift Meta. Русский перевод хранится отдельно, числа защищены при переводе. tools/render-builds.cjs заранее создаёт скрытые карточки на странице. app.js показывает одну карточку по data-item-key, закрывает её повторным нажатием, кнопкой «Скрыть» или Escape. При выборе другого значка, позиции или варианта сборки старая карточка скрывается. Описание видно и у ситуативных замен. Запросы к сторонним сайтам при нажатии не выполняются.

## Сложность освоения и положение описаний
champion-difficulty.json хранит собственную оценку Rift Atlas для всех 142 чемпионов: 1/2/3 по механике, комбинациям и принятию решений. Официальная оценка Riot сохранена отдельно в officialRiot, а исходный champion-catalog.json не переписан. Профиль показывает «Сложность освоения» и пояснение оценки в title. Зои, Шая и Ли Син имеют уровень 3. tools/profile-details.cjs применяет эти оценки при каждой сборке.
При открытии описания app.js переносит существующий блок .item-detail-region сразу после группы, в которой находится выбранный значок. Предметы раскрываются перед рунами, руны — под своим рядом; ситуативные замены раскрывают описание сразу под строкой замены. На телефоне блок занимает полную ширину, скрытие и повторное открытие не дублируют DOM.

## Порядок прокачки навыков
`app.js` подключает `skill-orders.js` только на странице чемпиона. Скрипт добавляет компактный блок после сборок и перед описаниями навыков. Иконки и русские названия берутся из уже существующего блока навыков. Внутри скрипта находятся данные для всех 142 чемпионов, поэтому отдельный сетевой запрос за JSON не нужен. При переключении позиции используется отдельный порядок, если он подтверждён; иначе явно показывается базовый порядок чемпиона. Таблицы источника с неверным количеством улучшений или уровнем ультимейта не показываются: для них остаётся только приоритет. `champion-skill-orders.json` хранит исходные данные и ссылки. Классы `.skill-leveling` и `.leveling-sequence` в `style.css` отвечают за оформление: 15 уровней в строку на ПК, по 5 на узком экране.
